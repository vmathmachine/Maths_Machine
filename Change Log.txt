=========== CALCULATOR BASED ================

POLYNOMIALS:

A new datatype "POLY" was added. This allows for you to represent multivariate polynomials. From there, you can add them, subtract them, multiply them, raise them to whole-number powers, plug in specific values for specific variables, and partial-differentiate them with respect to a specific variable.

To create a polynomial, simply type out a polynomial using single-letter unused variable names. When the system sees a variable that hasn't been assigned a value (or one whose assigned value is incompatible with the current operation), it casts that variable to a polynomial. Note that e and i cannot be used as polynomials, as they're already taken.




FUNCTIONS:

== of numbers: ==
Bernoulli numbers
Bernoulli polynomials
Chinese Remainder Theorem

A wide variety of statistical functions were added. This includes the PDF/PMF, CDF, quantile, and randomizer functions for several different distributions. It also includes functions that can calculate the mean, variance/std, range, median, arbitrary quantile, and arbitrary sample cumulants of a set of values, as well as one which calculates the line of best fit for a set of x's and a set of y's.

== for programming: ==

the throw() function was added. This, as you can expect, throws an exception. This can be used if you want to force an operation to stop conditionally.



GRAPHS:

You can now toggle labels / axes in 2D graph mode.


BUG FIXES:

The LCM of an empty set is now 1, as it should be.

Raising a matrix to the power of the biggest negative 32-bit integer previously caused a stack overflow error. This was because doing so would mean trying to negate the exponent, raise it to that power, and then invert it, but because negating that value yields the exact same value, this causes infinite recursion. This has now been fixed.

Analytic functions can now be used on degenerate matrices (i.e. ones where algebraic and geometric multiplicity of eigenvalues don't match) thanks to Jordan decomposition.

Previously, specific matrices (notably, [[0,1,0],[0,0,1],[1,0,0]]) would fail to generate their eigenvalues. The QR algorithm would just spiral into an infinite loop where it jumps back and forth between two equilibrium states instead of settling towards the state where QR=RQ and we can grab the eigenvalues. To fix this, a mechanism was added to detect loops and resolve them by nudging the matrix by an infinitesimal amount.

MISC:

Now, when you press on previous answers in the history menu, it copies over the exact value of that, not just whatever's there in text form. For more information on the specific mechanics of this change, please see the manual.

CalculationException (what's used to give error messages) was sped up by removing the stack trace for that specific type of exception

EnforceParamTypes was added as a more reliable way to track whether specific parameter types (such as whether a complex number input is an integer, if it has to be) are being passed correctly.

Tries were implementing to allow for expressions to be more quickly tokenized. This allows the calculator to start up faster as less time is spent trying to evaluate equations as they load in, and allows for answers to be given slightly faster as less time is spent just tokenizing the expression.
